# J. Shang — Technical Notes

Personal technical blog about AI systems, optimization, data processing, and large-scale training. The site is built with Astro and published as static HTML on GitHub Pages.

## Content model

Content is organized in three layers:

```text
topic → section → note
```

- Topic metadata and reading paths live in `src/data/topics.yaml`.
- Notes live under `src/data/notes/<topic>/`.
- `/topics/<topic>/` is generated by one shared topic template.
- `/topics/<topic>/<slug>/` is the canonical note URL.
- `/notes/` aggregates notes from every topic.

Muon is the first published topic. A data-processing topic skeleton is already present and can receive local or externally synchronized notes without adding another page template.

## Add a topic

1. Add an entry to `src/data/topics.yaml` with a unique `id` and section list.
2. Create `src/data/notes/<topic-id>/`.
3. Add notes whose `topic` and `section` match that configuration.

A locally authored note uses frontmatter like:

```yaml
---
title: "Parquet 基础"
description: "理解列式存储、编码与谓词下推。"
topic: "data-processing"
section: "storage"
slug: "parquet-basics"
date: 2026-07-14
order: 10
readtime: 8
---
```

The build fails when a note references an unknown topic or section, when a configured guide or featured note is missing, or when two notes resolve to the same canonical URL.

## Synchronize an external content repository

Imported bodies have a single source of truth: edit them in their source repository, not in the generated blog copy. Blog-only metadata such as topic, section, order, title, and description belongs in a manifest under `content-sources/`.

Muon synchronization:

```bash
# Inspect without writing
npm run sync:content -- \
  --topic muon \
  --source ../Muon \
  --dry-run \
  --discover

# Apply reviewed updates
npm run sync:content -- \
  --topic muon \
  --source ../Muon \
  --prune \
  --discover
```

The sync tool records the source path, file-level Git revision, sync date, and transformed-body hash. It refuses to overwrite local edits to a managed body. `--adopt` is only for the reviewed first import of existing unmanaged files; `--prune` is required before managed files removed from the manifest are deleted.

See `content-sources/README.md` for adding another external repository.

## Automation and deployment

- `.github/workflows/quality.yml` checks types, the production build, and local links on pull requests or manual dispatch.
- `.github/workflows/sync-muon.yml` checks the Muon repository weekly and on manual dispatch. Mapped changes are pushed to a dedicated branch and opened as a pull request for review; an unmapped new Markdown file fails discovery so it cannot be silently skipped.
- `.github/workflows/deploy.yml` repeats the type and local-link gates before deploying `main` to GitHub Pages.
