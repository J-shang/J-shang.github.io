## 如何读这张表

矩阵的比较单位是 `模型代际 × 训练阶段`，不是公司。它只做字段索引，不是透明度、数据质量或能力排行榜。

- `unknown`：公开资料不足，不能推断为零或“没有做”。
- `ambiguous`：来源给了说法或数字，但统计单位/阶段不足以严格比较。
- `n/a`：该字段按定义不适用于这一行。
- token 数仅在同一行的来源定义内成立；不同 tokenizer 和 loss mask 下不得直接相加。

## 当前能支持的综合判断

- `[综合判断 | supported]` D4 级开放资产使“某个数据/顺序/阶段决策如何影响训练轨迹”成为可设计的研究问题；它不自动给出因果答案。
- `[综合判断 | supported]` OpenAI 从 GPT-3 到 GPT-5.6 的公开资料仍说明 source 类别和部分安全过滤，但最新代际不再提供可比较的 token mixture、cutoff 或 pretraining validation contract。
- `[未知 | open]` 不能从 GPT-5.6 的 benchmark、tokenizer 或模型回答反推出训练 mixture；这些推断不会录入本矩阵。
- `[综合判断 | supported]` “pretraining data”必须拆分训练阶段。OLMo 2 的 4T base 与 50B annealing、OpenAI 的 base training 与 reasoning RL 都不能作为同质 token 数相加。
- `[综合判断 | supported]` Llama 3 表明 data-mix proxy 的收益会随模型规模反转；小模型 annealing 适合筛选候选，不是 target model 效果的无条件替代。
- `[综合判断 | supported]` DeepSeek LLM 表明 filter/remix 变化会改变 fitted scaling exponents；因此 scaling law 依赖数据分布，不能把 exponent 当成跨语料的质量分数。
- `[综合判断 | supported]` DeepSeek R1/V3.2/V4 展示了三种不同 synthetic-data relation：rejection-sampled SFT、verifier-backed agent RL、on-policy multi-teacher distillation；把它们都记成“合成数据”会掩盖监督信号和失败模式。
- `[综合判断 | supported]` Qwen2 的 7T/12T 反例与 Qwen2.5-Coder 的 mixture/filter ablation 表明，data scale、threshold 与配比必须在固定模型和 token budget 的局部实验中解释，不能单独用 retained tokens 排序。
- `[综合判断 | supported]` Qwen3 将 extractor、refiner、generator、instance annotator、off-policy teacher 与 on-policy teacher 分成不同角色；model-mediated data 需要 provenance graph，而不是一个 synthetic 布尔字段。
- `[综合判断 | supported]` MiMo 把 extractor recall、dedup、quality reweighting、mixture 和 context curriculum 串成连续链；其中任何一个版本变化都可能改变 reasoning-pattern density，不能只审最终 filter score。
- `[综合判断 | supported]` MiMo 的 RL/agent 材料显示 problems、successfully built environments、rollouts、trajectories、tool calls 与 loss tokens 是不同统计层；MOPD 还需要 student/teacher checkpoint 与 logits provenance。
- `[综合判断 | supported]` MiniMax-01 把 seed variance、MDE 和 statistical power 纳入 data proxy protocol；这使“没有显著差异”能与“实验功效不足”分开，但仍不能保证 40B-token proxy 的排序迁移到最终模型。
- `[综合判断 | supported]` MiniMax 的 repetition-matched proxy、Text long-context curriculum 与 VL pair/token 双重核算说明：小预算实验、长上下文 exposure 和多模态 pair 数必须各自定义分母，不能折叠成一个训练 token 总数。
- `[综合判断 | supported]` MiniMax M1/M2 把 synthetic data 从单一类别拆为被降采样的 synthetic reasoning、可验证 logic/code tasks、反向合成专业任务和 artifact-aligned trajectories；质量控制依赖不同 verifier，不能共用一个 acceptance rate。
- `[综合判断 | supported]` Moonlight的同预算optimizer对照说明token efficiency可以在固定data/order下研究；K2同时更换MuonClip、rephrasing与MoE sparsity，final gain不能回填为单一optimizer或data因果。
- `[综合判断 | supported]` K2的rephrasing增加surface diversity而不增加independent source evidence；应保存source→rewrite lineage，并按source group审计fidelity与validation leakage。
- `[综合判断 | supported]` K2/K2.5把agent data扩展为tool、agent、task、rubric、trajectory、environment state和verifier闭环；Agent Swarm还要求分开报告wall time与total generated tokens。
- `[综合判断 | supported]` K2.5固定mixed-token budget的fusion实验有价值，但timing与vision ratio耦合；其结果支持tested combination排序，不支持两个因素的独立普遍规律。
- `[综合判断 | supported]` GLM-4.5/5 的阶段算术说明 headline token 可因舍入与边界适配不闭合；必须保留分项、context、unique/sample/loss 单位与 architecture-adaptation 归属，而不是修改原始数字使其强行相等。
- `[综合判断 | supported]` GLM 的 agent 链路将 repository/URL、task、environment、trajectory、exact token IDs、judge 与 loss mask 串成 provenance graph；“>10K environments”不能替代 rollout、tool-call 或 supervised-token accounting。
- `[综合判断 | supported]` Step 3.5 把 14.6T broad、3T annealing 与 750B mid-training闭合到 context/replay 层，但 mixture、LR、mask、RoPE、router 与 context 联合改变；公开结果只能支持联合配方，不能单独识别 annealing corpus 因果。
- `[综合判断 | supported]` Step Law 的 3,700-run 网格适合预测 tested setup 内的 LR/batch，不是 mixture optimizer；STEP3-VL 的 sample family、1.2T multimodal tokens 与 nominal rollout counts 也必须保留三套分母。
- `[综合判断 | supported]` MAI 的 29.2T unique/30T sampled/epochs 表与 23B-active rank reversal证明 mixture utility 会随scale、horizon、novelty saturation变化；小模型代理必须经过scale-up gate，不能默认rank invariant。
- `[综合判断 | supported]` MAI pretraining 的 human-generated-only 与 Phi-4 的 synthetic-heavy 是两个独立family recipe；Phi表中的40%不含15% web rewrites及code内synthetic，阶段/类别边界比单一synthetic比例更重要。
- `[综合判断 | supported]` Claude Opus 4的150K transcript事件表明污染会注入format-conditioned world assumptions，而不只是抬高benchmark；canary能建立targeted artifact lineage，但不能覆盖删除marker、OCR、翻译或语义近重复。
- `[综合判断 | supported]` Claude的consumer opt-in、commercial default exclusion、feedback/safety review与Development Partner Program是不同consent路径；当前政策不可倒推历史checkpoint，system-card eval透明度也不能补足token/mix未知项。
- `[综合判断 | supported]` Google材料必须分成Gemini production、Gemma open-weight和WebLI/JEST research三层：Gemma 3的token/context recipe与JEST的selection效率都不能补成Gemini训练事实。
- `[综合判断 | supported]` Gemini 1.5的10M是命名stress test中的context上限，不是10M训练序列证明；Gemma 3则明确32K pretraining后在末段把4B+扩至128K，说明serving、testing和training exposure必须分列。
- `[综合判断 | supported]` JEST的learnability score由learner loss减reference loss构成，reference的curated distribution会进入selection policy；因此报告效率时还必须审计reference provenance、scoring FLOPs和per-domain acceptance。
- `[综合判断 | supported]` Gemma 4展示了open weights与quantitative recipe disclosure可以背离：权重可下载、source/cutoff已知，但token ladder、mixture、context-extension exposure仍为`open`。
- `[综合判断 | supported]` Grok的X ecosystem至少有training snapshot、inference-time X Search、eligible data sharing与future training四层；实时答案或政策允许使用public posts都不能证明某个checkpoint的X mixture。
- `[综合判断 | supported]` xAI的“trillions to tens of trillions”是跨models/dynamic datasets的family range，缺少model/stage/unique-sampled-loss索引，不能填入Grok 3或4的单模型token栏。
- `[综合判断 | supported]` Grok 4.1/4.20明确把targeted mid-training放在P0和SFT/RL之间；即使corpus/token未知，也必须保留独立阶段，不能归入domain SFT。
- `[综合判断 | supported]` Grok 4.5的数十万RL tasks需要展开为repository/environment/task/rollout/tool/reward/loss provenance；task count不能替代trajectory或token accounting。
- `[综合判断 | supported]` Seed1.5-VL的3T corpus headline与16B+3T+240B阶段和属于不同披露口径；在没有manifest和repeat/loss统计时，应保留3.256T算术与关系`open`，不能强行改写原数字。
- `[综合判断 | supported]` Seed-Coder把GitHub code、commit与web做成三条管线，并以high-recall FastText→LLM scoring形成cost-aware cascade；各层candidate rate、recall/precision和retention不能合并成最终“质量率”。
- `[综合判断 | supported]` Seed-OSS的Base/woSyn配对checkpoint比跨厂商benchmark更接近synthetic-data attribution，但必须核对总budget、order、seed与replacement；部分指标退化也反驳“synthetic普遍有益”。
- `[综合判断 | supported]` 豆包当前产品policy只能建立content→training eligibility关系；selected pool、transform、sampling与named-checkpoint inclusion仍需独立lineage。
- `[综合判断 | supported]` Hunyuan-Large把近1.5T instruction-shaped synthetic data放在P0，TurboS又把instruction/LongCoT前移到annealing；训练阶段必须按更新位置/目标定义，不能按样本格式定义。
- `[综合判断 | supported]` TurboS的16T headline与16.35T已知stage sum、A13B的20T headline与至少20.3T known exposure说明摘要总量可能不覆盖后续context阶段；矩阵应并列来源数字、阶段算术和未知项。
- `[综合判断 | supported]` TurboS在model-based extraction后做global semantic dedup，因此extractor版本改变dedup对象；复现semantic threshold不足以复现retention。
- `[综合判断 | supported]` HunyuanOCR的200M image-text pairs、454B stage tokens和cross-task reuse表明unique pair、task instance、sampled token与loss token必须四层核算；同图跨任务还要求group-level split。
- `[综合判断 | supported]` Hy3公开base/instruct weights与fine-tuning pipeline，但未公开P0 source/token/mix；artifact openness与data-recipe openness可以显著背离。
- `[综合判断 | supported]` ERNIE 3.0的knowledge enhancement包含KG fact→triple-sentence alignment→UKTP objective；ERNIE 4.5的knowledge labels/key-point synthesis主要作用于analysis、mixture和generation，两者不是同一机制。
- `[综合判断 | supported]` ERNIE 4.5 REEAO能使global token sequence不受node/batch/restart影响，但无法补足raw snapshot、parser/filter/tokenizer与manifest未开放；delivery reproducibility不等于corpus reproducibility。
- `[综合判断 | supported]` ERNIE 4.5 token-balanced loss以total sequence positions归一化、仅对unmasked output text求和，说明sequence tokens、modality tokens与loss tokens必须同时保存。
- `[综合判断 | supported]` ERNIE 5.0的text NTP、visual frame/scale与audio codec targets共享backbone却不共享自然单位；“统一token空间”不能成为跨模态单一质量或成本分数。
- `[综合判断 | supported]` ERNIE 5.1约6% pretraining cost来自5.0 elastic super-network继承，不是独立from-scratch data ablation，也不能换算成6% corpus。
